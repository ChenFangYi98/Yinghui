# 映绘 Yinghui 0.4.5

本轮完善本地看图模型的连接可靠性、独立环境设置，以及大致圈画后的对象识别和双模型协作。项目格式保持 v15，已有项目、连接和凭据继续沿用。

- 新增离线 Qwen3.8-27B UD-Q4_K_M 多模态助手及匹配的 F16 视觉编码器，共约 17.4 GB；保留约 1.95 GB 的 Qwen3.5 2B。权重按固定来源版本下载，逐文件核对大小与 SHA-256，随包提供许可证。27B 负责理解图像和调用工具，图片像素由独立图片模型生成。
- 模型设置中选择看图型号，各型号分别保存设备、上下文和线程数。支持独立模型包、CPU / CUDA / Vulkan 运行库路径、加载超时及恢复默认环境。Qwen 图片型号分别保存设备、步数、输出尺寸和备用引擎；开发者脚本可编辑、备份、检查语法和恢复。
- 本地连接绕过系统代理。每次启动刷新随机端口与临时认证，模型运行期间持续检查健康状态；服务失去响应后可重新加载，失败不会自动重复修图。外部 GPU / Python / llama.cpp 参数不再污染随包推理进程。
- 大图片模型推理前释放软件自己的看图模型显存；图片完成后卸载自己图片服务的显存缓存，后续语言调用按需恢复看图模型并获取新连接。软件内 AI 任务顺序执行，排队可取消，界面和普通编辑保持可用。用户原有 ComfyUI 不被关闭或卸载。
- 助手增加“大致位置 · 识别完整对象”。文字模型获得干净整图、标记图和局部放大图，先给出原图坐标中的对象框；MobileSAM 识别实际区域，随后一轮检查实际蒙版，再执行编辑。完整物体和物体部位采用不同识别提示，避免将整辆车误选成车门。
- 最多支持八块独立位置标记，检查每块标记的覆盖和识别面积，定位失败不提交。只使用图片模型时，根据标记框进行本机对象识别，再发送整图及蒙版。此方式缺少文字模型的语义定位能力，复杂对象建议双模型或精确圈选。
- 精确圈选不会扩大；明确亮度、曝光等数值要求始终沿用原蒙版。大致位置模式只在识别后的实际蒙版内合成，范围外像素逐一检查。成功修改保存前后版本，可整句撤销、重做和继续修改；取消、失败和旧修订不提交。
- 修复“只调用一次图片工具”在大致位置模式下错误耗尽工具预算的问题，允许先定位、再执行一次实际编辑；只定位而没有编辑时明确提示原图未修改。
- 大权重校验改用 Windows CNG SHA-256，并缓存与包路径、清单、文件大小及时间戳绑定的验证结果；文件或清单变化后重新验证。修复清单文件保持打开导致更新无法原子替换的问题。

完整便携目录可直接运行，公开交付另提供 0.4.5 分卷完整安装器；已有 0.4.3／0.4.4 完整版可覆盖包含新权重的更新 ZIP。安装器的 `.exe` 与所有 `.bin` 分卷必须放在同一文件夹。

运行库隔离和 CPU 回退不能保证任意驱动、硬件容量、损坏文件或自定义代码均可运行。27B 建议至少 32 GB 内存，低配置可手动选择 2B；图片模型 CPU 推理可能很慢。复杂人体、遮挡、透明边缘与生成画质仍需预览检查。

实际测试、性能记录和未验证项目见 [0.4.5 验证记录](VALIDATION-0.4.5.md)。
