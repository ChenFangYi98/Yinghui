# Compositor Windows 0.3.1 功能与可靠性复审

日期：2026-10-10。对象：当前 Windows 源码、已有 0.3.1 构建、验证记录和界面截图。

这是0.3.1历史审计。2026-10-11的修复和新增能力见[0.4.0实施记录](IMPLEMENTATION-0.4.0.zh-CN.md)，实际测试见[验证记录](VALIDATION.md)。以下发现保留用于追溯。

结论：基础修图、中文界面、区域标记、非破坏调色、配置记忆、自动版本和部分 AI 工具链已可用；
目前仍是阶段版。距离“新手主要用语言完成修图，专业模式具备完整 Photoshop 能力”的目标还有明显缺口。
应先修复 AI 作用范围约束，再扩展工具与专业内核。

本次只审核，未修改应用源码、项目格式或安装包。新增审计复现使用本机模拟服务和合成图片，
没有发送真实照片、读取真实服务密钥或发起收费云端调用。

## 1. 优先修复的问题

P1 表示可能改错对象或范围，应在继续扩大自动应用之前修复。P2 表示连续操作、可靠性或体验问题。

### A01 · P1：普通局部指令可能放开选区限制（已复现）

- 条件：已有小选区，输入“把选中的区域自然提亮”，模型返回重新选择区域的工具调用。
- 实际结果：`选中.*区域` 被解释为用户授权改变选区；模拟模型把选区扩大为整图后再提亮，
  原来选区外的像素也改变，任务仍返回成功结果。
- 原因：`selectionRequest` 通过宽泛正则推断授权；随后将新选区并入 `allowedRegion`。
  “原始选区以外不变”的检查因此改为检查扩大后的区域。
- 代码：[授权判定](src/ai/AIEditCoordinator.cpp#L386)、[扩大保护区域](src/ai/AIEditCoordinator.cpp#L558)。
- 修复建议：区分“引用已有选区”和“请求建立/修改选区”；把原始允许区域保存在不可变任务约束中。
  模型不能自行扩大范围。即使允许重选，也应由软件按明确的用户意图授权具体步骤。
- 回归标准：上述中文句式及“当前选中区域”“圈中的地方”等同义表达，均不能授权 `select_rect`、
  `deselect`、反选或整图调整；原始蒙版外像素逐点不变。

### A02 · P1：AI 可以绕过“当前图层”目标（已复现）

- 条件：两个未锁定图层，界面选择“当前图层”，模型显式传入另一个图层的 ID。
- 实际结果：当前图层不变，另一个图层的亮度增加 5，任务仍返回成功结果。
- 原因：软件只在模型未填写 `scope` / `layer_id` 时补默认值，没有强制验证固定目标。
  提交检查验证文档、修订号和选区，未落实 `EditPlan.target` 的图层/范围限制。
- 代码：[默认值填充](src/ai/AIEditCoordinator.cpp#L403)、[提交检查](src/core/Editing.cpp#L576)。
- 修复建议：执行前统一验证每条命令的读写对象；当前图层操作只能修改授权图层。
  新增图层、跨图层合成等命令需要明确的命令级作用范围，不能仅依赖模型提示词。
- 回归标准：错误 `layer_id`、`scope=document`、跨图层删除/透明度/变换等请求被整组拒绝；
  用户明确要求的跨图层任务仍能正常执行。

### A03 · P2：“刚才那块”不能可靠找回 AI 建立的区域（数据已复现，界面路径经源码确认）

- 条件：开始没有选区，AI 在任务中建立区域并提亮；之后取消选区，再说“刚才那块再亮一点”。
- 实际情况：任务修改后的文档有选区，但记录中的修改前版本没有选区。
  当前续改逻辑只恢复 `before_version_id` 的选区，会提示“上次操作没有局部区域”。
- 代码：[续改恢复逻辑](src/ui/AIPanelAgent.cpp#L130)。
- 修复建议：成功任务单独记录实际目标图层、区域 ID、原始蒙版和坐标映射；
  续改读取成功操作的目标，不能依赖任务开始前碰巧存在的选区。
- 回归标准：手动圈选、AI 点选、AI 矩形选区在清除标记后都可续改；发生裁剪、缩放或图层移动时，
  正确映射或要求重新标记，不能猜测位置。

### A04 · P2：手动编辑的版本保存缺少有序队列和失败重试（源码风险，未做退出故障复现）

- 每次手动事务独立提交一个 `QtConcurrent` 任务。存储有互斥锁，但并不保证按编辑发生顺序写入；
  `checkpoint` 的“修改前”和“修改后”也分别持锁，可与其他任务交错。
- 失败只显示短暂状态提示，没有待保存队列与重试入口；关闭文档只检查普通项目保存状态，
  没有版本任务的显式排空流程。
- 不据此断言已经发生数据丢失；当前实现尚不能证明快速连续编辑、磁盘满和退出时每次版本都可恢复。
- 代码：[后台任务](src/ui/MainWindow.cpp#L847)、[版本写入](src/io/VersionStore.cpp#L139)、
  [关闭文档](src/ui/MainWindow.cpp#L1251)。
- 修复建议：每文档按事务序号排队，由一个后台写入器执行；显示“版本已保存 / 待保存 / 失败”，
  保留失败快照，支持重试并在退出时处理待保存任务。AI 已有提交前版本保存和失败保留机制，应统一复用。
- 验收：连续编辑后版本顺序稳定；磁盘不足时仍保留当前文档与待保存结果；退出、重启可恢复最后已提交事务。

### A05 · P2：大图仍有主线程阻塞与重复计算（源码风险，需增加普通电脑基准）

- 打开图片/PSD/项目、置入图片、替换图片、部分拼图图片解码在主线程进行。
- 导出前缩放在启动后台导出之前执行；版本恢复和比较也在界面线程同步解码/合成。
- AI 局部高清图通过先合成整张原尺寸画面再裁切得到；每步保护检查又合成原尺寸结果并扫描选区外像素。
  这些检查必要，但不能无限叠加全图计算成本。
- 本机模型每次推理重新计算模型文件 SHA-256；对象点选每次重新运行 MobileSAM 编码器。
  已缓存推理会话，尚未缓存同一画面的图像 embedding。
- 代码：[打开/置入](src/ui/MainWindow.cpp#L982)、[导出缩放](src/ui/MainWindow.cpp#L1213)、
  [版本比较](src/ui/VersionDialog.cpp#L83)、[AI 局部图](src/ai/AIEditCoordinator.cpp#L119)、
  [像素保护](src/ai/AIEditCoordinator.cpp#L363)、[模型校验/编码](src/ai/LocalVision.cpp#L51)。
- 优化：可取消的后台加载；按文档修订号缓存合成画面和 SAM embedding；缓存已校验模型身份并处理文件变化；
  以脏区域和共享分块减少重算，保留独立的完整正确性校验。增加 8/16 GB 内存电脑上的峰值内存、首帧和交互延迟测量。

### A06 · P2：缩略预览与导出的细节还没有完整一致性保证（已知实现边界）

- 同一处理顺序已实现，但缩略预览先缩小原图再计算；模糊、锐化、降噪、纹理和颗粒等不能仅凭参数缩放保证完全一致。
- 代码：[缩小后调整](src/core/Compositor.cpp#L339)，现有 [README](README.md#L110) 已说明采样误差。
- 建议：提供原尺寸局部检查和明确的最终质量状态；对透明边缘、锐化光晕、噪声、文字与图层效果建立图像样本及误差标准。
  “同一管线”与“不同预览尺寸逐像素一致”需分开验收。

## 3. 最值得做的体验优化

1. **简单模式真正围绕一句话。** 保留一个输入框，让软件选择本机工具或图片模型；隐藏连接/模型/参数细节，
   需要时再展开。把取消、当前步骤和“已保存版本”固定在可见位置。现有 150% 缩放截图中输入和发送可见，
   进度/取消仍需向下滚动，应优先调整面板高度分配。
2. **让人一眼知道改哪里。** 持续显示标记叠层与“仅调整这里”；对象可命名、编号、保留，
   支持“这个人”“左边这个商品”“刚才那块”。定位有歧义时提供画面上的选择，减少术语提问。
3. **把连续修改做成可见的任务历史。** 每句话显示修改摘要、版本缩略图、比较、撤销、重做和换方案；
   清楚区分执行中、待保存、已应用、失败。保留当前作品而不是让用户重新开图或重输想法。
4. **补齐“改已有内容”。** 优先开放已有中文文字的改字/字体/字号/颜色/位置、图层重排、背景替换、
   局部修复和扩图；这些比新增大量滤镜更有助于语言修图闭环。
5. **减少新手操作分叉。** 首页拼图先选照片，海报直接点占位图换照片、点文字改内容；
   背景向导每一步可操作并看到效果。已有快速面板支持多选拼图照片和替换图片，应统一到首页流程。
6. **工具能辨认。** 当前多个工具共用方框加点的图标，提示统一为“拖动使用”，不适合点选对象等操作。
   应使用独立图标、准确动作说明、离线示例；六个教程升级为可跳过的交互引导。
7. **专业界面逐项交付。** 先完成多图层操作、精细选区、变形和可编辑文字，再扩展 RAW/高位深/CMYK。
   不应只新增菜单名称或将图片重绘当作可编辑液化。
8. **发布体积与语言完整性。** 可考虑可选离线模型包；英文切换后部分 AI、版本、模板文案仍为中文，
   需集中资源管理与完整性检查。

截图依据：[150% 简单模式](out/ui-validation/simple-150.png)。

## 4. 测试与真实验证还缺什么

- 已有记录为 **74 个测试用例通过**；本次没有改应用源码，也没有重跑整套测试。
  新增三项审计探针重现了上述缺陷，不代表这三个功能验收通过。
- Kimi：实际工具调用和合成图识别通过，但完整 Agent 流程遇到 429，不能标记完整通过。
- Ollama `qwen3.5:latest`：此前已验证选区亮度 +5 的真实完整流程；不代表所有宽泛目标和复杂素材都通过。
- 其他云端对话服务、云端图片模型、ComfyUI 实际模型执行：仍主要是模拟验证或未实测。
- RTMPose：原生样本推理存在，未完成重新导出与 PyTorch 一致性验证，也没有瘦身端到端流程。
- Windows 10、无开发工具的干净环境、真实中文候选窗、真实数位板、远程 Windows CI：未完成本轮实测。
- 性能已有 4000×4000 / 800 px 画笔基准，但机器为 i9 + 128 GB 内存；
  需要普通内存配置、长时间编辑、多个文档、版本积压、低磁盘空间、退出恢复和损坏文件压力测试。
- 应增加真实人像、商品图、中文海报、复杂合成及绘画样本，分别验收目标定位、边缘、背景和连续修改；
  不能以协议模拟通过代替画面质量验收。

详细基线见 [VALIDATION.md](VALIDATION.md)。

## 5. 建议的实施顺序

1. **可靠性修复版：** A01/A02 的主机约束、A03 成功目标记忆、A04 有序版本队列；增加针对错误模型工具调用的回归测试。
2. **语言修图闭环：** 统一助手与图片入口，接入扩图、已有文字修改、图层管理和局部修复；完善任务历史、歧义选择和失败重试。
3. **新手流程与性能：** 首页拼图/海报替换、交互教程、固定进度/取消；后台加载、局部缓存、SAM embedding 复用，普通电脑基准。
4. **专业内核分阶段：** 先变形/液化和多层/精细选区，再 PixelSurface/PixelFormat/ColorContext/FilterGraph、RAW/高位深/CMYK/智能对象。
   新对象保存时同步格式版本、迁移与兼容测试，不能只修改版本常量。
5. **发布验收：** 完成约定服务真实调用、Windows 10/11 干净安装、输入法/数位板和 Photoshop 复杂样本验证后，再发布对应能力声明。
